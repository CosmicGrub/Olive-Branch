Both tracks are drawn in the child's local time. That is the doctrine: child-local is canonical, everything else is a rendering. The bands are day-parts, not clock hours — so bedtime stays 8:30 PM through both daylight-saving transitions and through a summer move to Texas.

02

Async delivery engine

0.2.0

An intent carries a policy, not a timestamp. scheduled_at is a cache that goes stale whenever the child travels, a bedtime shifts, or daylight saving flips — so it is rematerialized on every dependency change plus a nightly sweep.

04

Data model — child as root

0.1.0 · 0.2.0

Modelling account → family → children breaks the instant parents separate, remarry, or a protective order lands. The child is the root entity and guardianship is an edge carrying its own scope, validity window, and court reference.

Root
child — display name, birth date, home_tz fallback, privacy_tier
Edges
guardianship — role, scope jsonb, supervised, order_ref, validity range
guardiantrusted_adultsupervisedrestricted
Temporal
child_tz_interval — non-overlapping timeline, GiST exclusion constraint
day_part — wall-clock time, per household, per season
Async
delivery_intent — policy, targets, materialized cache, expires_at NOT NULL
Custody
custody_order.order_tz — “Friday 6:00 PM” is meaningless without it; never default to the server zone
Lists
child_list_item — wants and needs strictly separated; claimed_by never surfaced to the child

The paid tier

PHASE 4 · IN PROGRESS

Reach

  • Trusted-adult role — shipped (scoped guardianship edge)
  • Realtime co-op during calls — shipped for several games
  • iOS — not built. Dart client passes strict analysis and 14 widget tests, but only Android/Windows kiosk bridges are drafted; no iOS Guided Access bridge exists yet
  • Native kiosk bridges — drafted, unverified. Real device/emulator compilation needs a toolchain this environment doesn't have

Two real open decisions block further Phase 4/2 work: §16.2 #6 (self-host vs. LiveKit Cloud) and §16.2 #8 (curriculum standards source). See CHANGELOG for the full decision log.
